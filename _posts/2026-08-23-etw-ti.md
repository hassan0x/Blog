# ETW-TI notes (WinDbg)

`Microsoft-Windows-Threat-Intelligence` is a kernel ETW provider. Defender (`DefenderApiLogger`) and EDRs subscribe. Ordinary processes cannot — consumers are PPL-Antimalware.

GUID `{F4E1897C-BB5D-5668-F1D8-040F4D8DD344}`. Always hashes to bucket **29**.

ETW roles: **provider** fires → **session** buffers → **consumer** reads. If no session, `IsEnabled=0` and the kernel skips the event (no cost).

`.reload /f` first if names do not resolve. LiveKD is read-only — `eb` needs a writable kernel debug session.

| Event | Trigger |
|-------|---------|
| `ALLOCVM` | `NtAllocateVirtualMemory` with exec |
| `MAPVIEW` | `NtMapViewOfSection` into another process |
| `READVM` / `WRITEVM` | cross-process memory |
| `PROTECTVM` | change to exec |
| `QUEUEUSERAPC` | APC inject |
| `SETTHREADCONTEXT` | context hijack |

## Two ways to the same `_ETW_GUID_ENTRY`

```
A  nt!EtwpDebuggerData[3] → silo → GuidHashTable[29] → walk Flink until GUID
B  nt!EtwThreatIntProvRegHandle → _ETW_REG_ENTRY → GuidEntry (+0x20)
```

**B first** (two `dq`). **A** if the handle is NULL or GUID mismatch.

![chain](/assets/images/etw-structure-chain.svg)

```
_ETW_GUID_ENTRY
+0x000  List              LIST_ENTRY (bucket chain)
+0x028  Guid              16 bytes  ← first DWORD Data1 = 0xF4E1897C
+0x060  ProviderEnableInfo  _TRACE_ENABLE_INFO  (OR of all slots)
+0x080  EnableInfo[8]     one slot per session, each 0x20
+0x188  SiloState         back-pointer to silo

_TRACE_ENABLE_INFO
+0x000  IsEnabled         1=on, 0=off  ← eb this
+0x004  Level
+0x008  MatchAnyKeyword
+0x01C  LoggerId          index into EtwpLoggerContext

_ETW_REG_ENTRY
+0x020  GuidEntry         → _ETW_GUID_ENTRY
```

`+0x028` / `+0x060` / `+0x080` are **hex**. Slot `s` = `entry + 0x80 + s*0x20`.

---

## B. Direct handle (preferred)

```
dq nt!EtwThreatIntProvRegHandle L1
```

NULL → provider not up, try A.

```
dq <reg>+0x20 L1
dt nt!_ETW_REG_ENTRY <reg> GuidEntry
```

That pointer is `_ETW_GUID_ENTRY`.

```
dd <entry>+0x28 L1
```

Expect `f4e1897c`. Wrong → not TI, use A.

RVA:

```
? nt!EtwThreatIntProvRegHandle - nt
```

## A. Hash table (fallback)

### Silo root

```
dp nt!EtwpDebuggerData L4
```

4th pointer (`+0x18`, index 3) = `_ETW_SILODRIVERSTATE`. Save it.

```
? nt!EtwpDebuggerData - nt
```

### Dump silo

```
dt nt!_ETW_SILODRIVERSTATE <silo>
```

| Field | Off | Use |
|-------|-----|-----|
| `EtwpLoggerContext` | `+0x1C8` | session array (names, optional) |
| `EtwpGuidHashTable` | `+0x1D0` | 64 buckets, **embedded** (`silo+0x1D0`) |

### Bucket size

```
?? sizeof(nt!_ETW_HASH_BUCKET)
```

Expect `0x38` (56). Bucket 29 offset = `29 * 0x38 = 0x658`.

TI GUID hash (fixed):

```
(Data1 ^ Data2Data3 ^ Data4[0] ^ Data4[4]) & 0x3F
= (0xF4E1897C ^ 0xBB5D5668 ^ 0xF1 ^ 0x04) & 0x3F
= 0x1D = 29
```

### Bucket 29

```
dt nt!_ETW_HASH_BUCKET <silo>+0x1D0+0x658
```

`Flink` = first `_ETW_GUID_ENTRY`. Empty if `Flink == Blink ==` bucket head.

### Confirm GUID (optional search)

```
s -b <HashTableBase> L?0x2000000 7c 89 e1 f4 5d bb 68 56 f1 d8 04 0f 4d 8d d3 44
```

Hit is `Guid` at `+0x28` → entry = hit `- 0x28`. Multiple hits = extra silos; keep the one whose `SiloState` (`+0x188`) matches the silo from `EtwpDebuggerData`.

Walk Flink until `Data1 == 0xF4E1897C` (what `etwti.c` does).

```
dt nt!_ETW_GUID_ENTRY <entry>
```

## List: is anyone listening?

Aggregate (fast path):

```
dt nt!_TRACE_ENABLE_INFO <entry>+0x60
```

`IsEnabled=1` → at least one session. Defender often has `MatchAnyKeyword = 0xFFFFFFFFFFFFFFFF`.

Eight slots (`+0x80`, step `+0x20`):

```
dt nt!_TRACE_ENABLE_INFO <entry>+0x80
dt nt!_TRACE_ENABLE_INFO <entry>+0xa0
… eight times
```

Note `LoggerId` where `IsEnabled=1`. Typical: 2–3 slots.

### Session name (WinDbg only — not in `etwti.c`)

```
dq <EtwpLoggerContext> + (LoggerId*8) L1
dt nt!_WMI_LOGGER_CONTEXT <result>
```

`LoggerName` e.g. `DefenderApiLogger`.

---

## Disable

Zero aggregate:

```
eb <entry>+0x60 0
```

Zero one consumer (slot 0 = `+0x80`):

```
eb <entry>+0x80 0
```

`etwti.c disable` zeros **aggregate and all 8 slots**.

Kernel then skips TI events. LiveKD cannot write.

## Commands

| Cmd | Does |
|-----|------|
| `dp` / `dq` / `dd` | dump pointers / QWORDs / DWORDs |
| `eb` | edit byte (`IsEnabled`) |
| `dt` | dump typed struct |
| `?? sizeof(...)` | type size, no memory read |
| `s -b` | byte search (GUID) |
| `poi(addr)` | read pointer at addr |

Offsets (`+0x1D0`, `+0x20`, `+0x60`, …) are build-specific — confirm with `dt` on the target. Bucket **29** is GUID-fixed.

## How `etwti.c` maps to these notes

WinDbg uses **symbols**. The C tool uses **kernel base + RVA**.

| Post | WinDbg | `etwti.c` |
|------|--------|-----------|
| RVA | `? nt!EtwThreatIntProvRegHandle - nt` | `RVA_ETW_TI_REG_HANDLE` |
| RVA | `? nt!EtwpDebuggerData - nt` | `RVA_ETW_DEBUGGER_DATA` |
| Handle | `dq nt!EtwThreatIntProvRegHandle` | `kread64(kbase + RVA_ETW_TI_REG_HANDLE)` |
| GuidEntry | `dq reg+0x20` | `kread64(reg + REG_ENTRY_GUID_OFF)` |
| Data1 | `dd entry+0x28` | `kread32(ge + GUID_ENTRY_GUID_OFF) == TI_GUID_DATA1` |
| Silo | `dp EtwpDebuggerData L4` 4th ptr | `kread64(kbase + RVA_ETW_DEBUGGER_DATA + 0x18)` |
| Table | silo `+0x1D0` | `SILO_GUID_HASH_OFF` |
| Bucket 29 | `+ 29*0x38` | `TI_BUCKET_INDEX * ETW_HASH_BUCKET_SIZE` |
| Walk | Flink until GUID | `node = kread64(node)` until Data1 match |
| Aggregate | `dt … entry+0x60` | `tiEntry + GUID_ENTRY_PROV_OFF` |
| Slots | `entry+0x80 + s*0x20` | `GUID_ENTRY_SLOTS_OFF` + `s * TRACE_SLOT_SIZE` |
| IsEnabled | `eb … 0` | `kwrite32(… + TEI_IS_ENABLED_OFF, 0)` |
| LoggerId | `+0x1C` | `kread32(slot + TEI_LOGGER_ID_OFF) & 0xFFFF` |
| Logger name | `EtwpLoggerContext[id]` | **not implemented** |

WinDbg `kread` = `dq`/`dd`. WinDbg `kwrite` = `eb` via RTCore64 (`kwrite32`).

`list` = method B, else A, then dump aggregate + enabled slots. `disable` = `IsEnabled=0` on aggregate and 8 slots.
